# Devlog — 2026-03-04

## 今日完成

### Bug Fix: PDF 下载功能修复
- **问题**：论文搜索后点击"下载 PDF"对非 arXiv 来源（PubMed、CrossRef、bioRxiv 等）始终失败
- **根因**：`_try_download_pdf()` 只做简单 `httpx.get(url)`，对落地页 URL 获取到 HTML 而非 PDF，返回 None。项目已有完善的 `PaperDownloader` 类但未被使用
- **修复**：
  - `_try_download_pdf` 改用 `PaperDownloader`（arXiv + Unpaywall DOI→OA + 直链三级策略）
  - `DownloadPdfRequest` 新增 `doi` 字段
  - 前端 `downloadPdf()` 传入 `result.doi`
  - 同步修复 `save_to_kb` 和 `download_and_analyze` 两个端点的调用
- **影响文件**：`src/api/routes/paper_search.py`、`src/api/schemas.py`、`web/src/api/paperSearch.ts`、`web/src/pages/PaperSearchPage.tsx`

### T-88: 测试体系改进 — 防止「测试通过但功能坏了」
- **问题**：198 个测试全通过，但 PDF 下载对 5/6 个搜索源完全不可用。所有测试用 MagicMock 替换了整个 HTTP 栈，跳过了所有验证逻辑
- **解决方案**：引入四层测试防护
  - **契约测试**（17 个）：用 `respx` 传输层 mock 拦截 httpx，让 content-type 检查、%PDF 验证等逻辑真正执行
  - **冒烟测试**（5 个）：`@pytest.mark.smoke` 标记，用真实 HTTP 验证 arXiv/Unpaywall/PubMed
  - **架构守护**（4 个）：AST 分析源码，强制 `_try_download_pdf` 使用 PaperDownloader、`_fetch_pdf` 检查 content-type 和 %PDF
  - **API 集成**（7 个）：TestClient 测试 /search、/download-pdf、/download-and-analyze 端点
- **基础设施**：pyproject.toml 新增 respx 依赖 + pytest markers（smoke/e2e），默认跳过 smoke 和 e2e
- **结果**：测试总数 198 → 231（226 默认运行 + 5 smoke），全部通过

## 遇到的问题

- 代码中存在功能重复：`_try_download_pdf`（简陋版）和 `PaperDownloader`（完善版）并行存在，新端点开发时未复用已有工具类
- MagicMock 反模式：mock 越多测试越「绿」，但离真实行为越远。关键教训：对含验证逻辑的 HTTP 客户端应使用传输层 mock（respx），不要用 MagicMock
